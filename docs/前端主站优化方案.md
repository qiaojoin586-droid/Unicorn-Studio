## 1. 现状总评

主站整体质量**中上**：深色主题视觉统一、路由级代码分割已做、错误态普遍带重试按钮、视频/轮播已尊重 `prefers-reduced-motion` 与 `saveData`、Node 层有完整的安全响应头（CSP/HSTS/反爬帧）、详情页有 404 兜底。这些是好底子，应当保持。

但从专业网站标准衡量，存在四类系统性短板：

1. **SEO 基本为零**——单页应用无每路由标题/描述/社交分享元信息，爬虫只能抓到一个空壳；更实际的是，**`robots.txt` 与 `sitemap.xml` 在现行服务的构建产物目录里根本不存在（已处于 404 状态）**，sitemap 源文件里的域名还是 `example.com` 占位符；
2. **一处前后端功能断裂**——后端 PV 埋点接口（`/api/stats/pv`）已实现并等待 `sendBeacon` 上报，但前端从未调用，后台仪表盘的流量数据永远是 0（注意：直接按 sendBeacon 默认方式上报会被后端以 415 拒收，见 F-02 的正确接法）；
3. **构建产物管理失序**——Vite 实际输出到 `frontend/frontend/`（`outDir: 'frontend'`），`dist/`、`release/` 是历史遗留，但三个产物目录共 114 个文件仍被 git 跟踪，`dist/` 中甚至残留着源码中已不存在的 `PrivacyPage` chunk，是典型的失真产物；
4. **细节打磨不足**——路由切换不回顶部、详情页标题残留污染、中文输入法回车误发送、AI 流式响应分包解析缺陷、4MB 背景视频未压缩等。

优先级定义（v1.1 收紧口径）：**P0** = 现行部署下今天就处于错误/缺失状态的功能；**P1** = 高频体验缺陷或显著影响专业度/性能的问题（其中 F-03～F-06 虽为 P1，但修复成本极低且用户感知强，随阶段一先行实施）；**P2** = 锦上添花，排期从容时做。

## 3. 问题详述与实施方案

### 3.1 P0：现行已损坏的功能

#### F-01 robots/sitemap 现行 404 + 构建产物目录失序

**机制澄清（v1.1 更正）**：`vite.config.js:11` 的 `outDir: 'frontend'` 意味着构建产物实际输出到 **`frontend/frontend/`**，Node 服务器服务的也是这个目录（`server/index.js:9` 的 `distDir = rootDir + '/frontend'`）。`frontend/dist/` 与 `frontend/release/` 是旧配置的历史遗留，现行构建流程**从不读写**它们。

**现状**：
1. `frontend/frontend/`（现行服务目录）中**不存在** `robots.txt` 与 `sitemap.xml`——两个地址今天就返回 404，搜索引擎无抓取配置可读。这不是"即将回归"，是"已处于错误状态"；
2. favicon **不受影响**：`index.html:5` 引用的 `/unicorn.svg` 由 Vite 从项目根目录解析并哈希打包进 `frontend/frontend/assets/unicorn-_qw6NVTm.svg`，构建正常。因此**以根目录 `frontend/unicorn.svg` 为准即可，无需迁移**；
3. git 跟踪的构建产物目录共**三个**（已逐一核实）：`frontend/dist/`（27 个文件，含已失真的 `PrivacyPage` chunk）、`frontend/frontend/`（51 个）、`frontend/release/`（36 个，其 `release/dist/` 内另有 robots.txt 与 sitemap.xml 旧副本）。

**方案**：
1. 新建 `frontend/public/`，放入 `robots.txt` 与 `sitemap.xml`（内容取自 `dist/` 旧副本并按 F-07 替换域名）；`unicorn.svg` 保持在项目根目录，不迁移；
2. `git rm --cached` 覆盖**全部三个**产物目录（`frontend/dist/`、`frontend/frontend/`、`frontend/release/`），使 ignore 规则真正生效（共 114 个文件）；
3. `scripts/smoke-test.js` 追加断言：`/unicorn.svg`、`/robots.txt`、`/sitemap.xml` 均返回 200。**注意路径是 `/unicorn.svg` 而非 `/favicon.svg`**（与 `index.html:5` 的实际引用一致，写错会误报失败）。

#### F-02 PV 埋点前后端断裂（含 415 规避）

**现状**：后端 `StatsController` 已实现 `POST /api/stats/pv`（`@RequestBody PvRequest`，忽略 DNT、IP 哈希、异步落库），注释明确期待"前台 sendBeacon 埋点"，但前端源码中无任何调用。后台仪表盘/统计模块的数据源因此恒为 0。

**接法要点（v1.1 更正）**：`@RequestBody` 走 Jackson，只接受 `Content-Type: application/json`；而 `sendBeacon(url, string)` 以 `text/plain`（CORS 安全列表类型）发送，Spring 会抛 `HttpMediaTypeNotSupportedException` → **415**。必须显式指定类型：

```js
// src/composables/useAnalytics.js
function reportPv(path, referer) {
  if (navigator.doNotTrack === '1') return   // 后端也判 DNT，此处短路减少无效请求
  const body = JSON.stringify({ path, referer })
  // 同源（经 Node 反代/Vite 代理）发送，JSON Blob 不触发 CORS 预检
  const queued = navigator.sendBeacon('/api/stats/pv',
    new Blob([body], { type: 'application/json' }))
  if (!queued) {
    // sendBeacon 返回 false（队列满）时降级
    fetch('/api/stats/pv', { method: 'POST', keepalive: true,
      headers: { 'Content-Type': 'application/json' }, body })
  }
}

router.afterEach((to, from) => {
  // 初始导航（vue-router START_LOCATION，from.matched.length === 0）才有真实外部来源；
  // 其余站内跳转（含从 / 跳出）一律记站内来源，避免把首页跳转误记为外部 referer
  const referer = from.matched.length === 0 ? document.referrer : from.fullPath
  reportPv(to.fullPath, referer)
})
```

**验收口径（v1.1 拆分）**：`DashboardService.summary()` 中今日 PV/UV 直读 `visit_log`，**埋点接入当天即可在仪表盘看到**；但近 7 日趋势读 `stats_daily` 聚合表，需等每日 01:00 定时任务落库，**当天看不到趋势图，次日验证**。限流桶为 60 次/分/IP，正常浏览足够，无需调整。

#### F-07 sitemap 占位域名

**现状**：`dist/sitemap.xml`（旧副本）内全部 URL 为 `https://www.example.com/`，文件自带 TODO 注释。随 F-01 将文件迁入 `public/` 时同步替换为正式域名；上线前无域名则保留 TODO 但必须在发布检查清单中列出。另外 sitemap 缺少详情页模板（作品/学习资料为动态路由，可后续由后端提供 sitemap 接口或构建期生成，列入 P2）。

### 3.2 P1：高频体验缺陷（修复成本极低，随阶段一先行实施）

#### F-03 路由切换不回顶部

**现状**：`router/index.js` 未配置 `scrollBehavior`。从首页底部点击"更多"进入作品列表页，视口停留在页面中部/底部。

**方案**：
```js
const router = createRouter({
  history: createWebHistory(),
  routes,
  scrollBehavior(to, from, savedPosition) {
    if (savedPosition) return savedPosition          // 浏览器前进/后退保留原位置
    if (to.hash) return { el: to.hash, behavior: 'smooth' }
    return { top: 0 }
  },
})
```

#### F-04 页面标题残留污染 + 路由参数变化不响应

**现状**：仅 `WorkDetailPage.vue:160` 与 `LearningDetailPage.vue:176` 在加载成功后写 `document.title`，且从不复位。浏览详情后返回列表，标签页标题仍是详情标题；其余页面从未设置过标题。

**附带隐患**：两个详情页只在 `onMounted` 中读取 `route.params.slug` / `route.params.id`（`WorkDetailPage.vue:145-168`），无参数 watcher。vue-router 在同一路由记录间跳转（如 `/works/a → /works/b`）会**复用组件实例**，`onMounted` 不再执行——当前页面结构下暂无此类入口，但属同源隐患，应一并修复。

**方案（v1.1 改为 watch 式）**：不要用 `onMounted/onUnmounted` 设置/复位标题（同样踩组件复用陷阱），改为 watch 响应式标题源：

```js
// src/composables/usePageTitle.js
import { watchEffect, onUnmounted } from 'vue'

export function usePageTitle(source) {
  const stop = watchEffect(() => {
    const t = typeof source === 'function' ? source() : source
    document.title = t ? `${t} - 独角兽工作室` : '独角兽工作室'
  })
  onUnmounted(() => {
    stop()
    document.title = '独角兽工作室'
  })
}
```

1. 7 个页面统一接入静态标题：首页「用创意点亮未来」、列表页「我们的作品」等；
2. 详情页传入响应式标题源 `() => work.value?.title`；同时将数据加载改为 `watch(() => route.params.slug, loadWork, { immediate: true })`，一并消除参数复用隐患。

#### F-05 中文输入法回车误发送

**现状**：`ChatInput.vue:11` 用 `@keydown.enter.exact.prevent="handleSubmit"` 发送，未判断 `event.isComposing`。中文用户用拼音输入法敲字、按回车确认候选词时，消息会被半截发送——对中文站点是高频场景。

**方案**：
```js
function onEnter(e) {
  if (e.isComposing || e.keyCode === 229) return
  handleSubmit()
}
```
模板改为 `@keydown.enter.exact.prevent="onEnter"`。

#### F-06 SSE 流式响应分包解析缺陷

**现状**：`useAiChat.js:36-44` 对每个网络分片直接 `chunk.split('\n')` 并筛 `data: ` 前缀。SSE 事件边界与 TCP 分包边界不对齐时，一行 `data: xxx` 会被切成两个分片：前半行缺 `data: ` 前缀被丢弃、后半行整体丢弃——AI 回复在弱网下偶发丢字。多行 `data:` 拼接、`[DONE]` 只跳出内层循环继续空读，也属同类不严谨。

**方案**：改为跨分片行缓冲，并按 SSE 规范兼容 `\r\n` 行尾（v1.1 加固；后端 `SseEmitter` 实际发 `\n`，不兼容时 `slice(6)` 会把 `\r` 带进正文）：

```js
let buffer = ''
let finished = false
while (true) {
  const { done, value } = await reader.read()
  if (done) break
  buffer += decoder.decode(value, { stream: true })
  const lines = buffer.split(/\r?\n/)
  buffer = lines.pop() ?? ''          // 最后一段可能是半行，留给下一分片
  for (const line of lines) {
    if (!line.startsWith('data: ')) continue
    const data = line.slice(6)
    if (data === '[DONE]') { finished = true; break }
    store.appendStreamingText(data)
  }
  if (finished) break
}
```
（UTF-8 多字节截断已由 `TextDecoder` 的 stream 模式正确处理，无需额外处理。）

### 3.3 P1：性能与资源

#### F-08 背景视频体积与播放策略

**现状**：`src/image/index.mp4` 3.95MB（首页）、`home.mp4` 1.23MB（学习页 + 加入页共用）、海报 200K/120K。视频组件已有 reduced-motion/saveData/出错降级三重防护（值得肯定），但：
1. 未压缩——4MB 对首屏是最大的字节开销；
2. 滚出视口后视频持续解码播放（首页场景：滚到服务/作品区后 Hero 视频仍在播放），移动端耗电耗内存。

**方案**：
1. 用 HandBrake/ffmpeg 以 H.264 CRF 26–28、`-preset slow`、720p、24fps 重编码，目标单文件 ≤ 1.2MB；有条件再产出 WebM（VP9）并 `<video>` 双 source 优先 WebM；
2. 海报图转 WebP（200K → 预计 < 60K）；
3. `BackgroundVideo` 增加 `IntersectionObserver`：视频元素离开视口即 `pause()`，回到视口 `play()`——**`play()` 返回 Promise，可能因浏览器自动播放策略 reject，必须 `.catch(() => {})` 吞掉**（视频本身 muted，通常不会触发，但保险起见）；同时监听 `document.visibilitychange`，页面隐藏时暂停；
4. 首页海报 `<img>` 加 `fetchpriority="high"`，视频保持 `preload="metadata"` 现状。

#### F-09 每路由 SEO 元信息

**现状**：`index.html` 仅有 title/viewport/icon，缺 `description`、Open Graph、`theme-color`、`canonical`。分享到微信/QQ/Twitter 无摘要与缩略图。

**方案**：
1. `index.html` 补全站默认值：`<meta name="description" content="…">`、`<meta property="og:title|og:description|og:image|og:type" …>`、`<meta name="theme-color" content="#030712">`、`<link rel="canonical">`；
2. 与 F-04 同层扩展为 `usePageMeta({ title, description })`，**同样采用 watch 响应式实现**（陷阱与 F-04 相同：同路由记录跳转时组件实例复用，`onMounted` 不重跑；原生 DOM 操作即可，站点规模无需引入 @unhead/vue）；详情页把作品摘要写入 description；
3. 补 `apple-touch-icon`（180×180 PNG）与 `.ico` 回退，iOS 添加到主屏不至空白。

#### F-10 `/uploads` 图片被强制 no-store

**现状**：`server/index.js` 的 `proxyToBackend` 对所有代理响应统一覆写 `Cache-Control: no-store`（本意是 SSE 不缓存），殃及轮播图等上传图片——每次进首页都全量重新下载。

**方案**：
```js
'Cache-Control': pathnameWithSearch.startsWith('/api/') ? 'no-store' : 'public, max-age=3600',
```
即：`/api/*`（含 SSE）保持 `no-store`，`/uploads/*` 给 1 小时协商缓存（文件名不含 hash，用 `no-cache`+ETag 亦可）。nginx 接管反代时同样按此区分。

#### F-14 useApi 无超时 + headers 合并顺序缺陷

**现状**（v1.1 补充第二处缺陷）：
1. `useApi.js` 裸 `fetch`，无超时与中止。后端挂起时所有页面加载态永久转圈；
2. 现有合并顺序有 bug：`{ credentials, headers: {...}, ...options }`——调用方一旦传入自定义 `headers`，会**整体覆盖**（含 Content-Type）而非合并。当前 `get/post` 不传 headers 故未暴露，属潜伏缺陷。

**方案**：一次性修正两处：
```js
async function request(url, options = {}) {
  try {
    const res = await fetch(BASE_URL + url, {
      ...options,                       // 先展开调用方配置
      headers: {                        // 再统一合并 headers，Content-Type 不可丢
        'Content-Type': 'application/json',
        ...options.headers,
      },
      credentials: 'include',
      signal: options.signal ?? AbortSignal.timeout(15000),
    })
    // …后续 res 处理不变
  } catch (err) {
    if (err.name === 'TimeoutError') {
      return { error: true, status: 0, message: '请求超时，请检查网络后重试' }
    }
    if (err.name === 'AbortError') {
      // 手动中止（调用方自带 AbortController 时）不伪装成超时
      return { error: true, status: 0, message: '请求已取消', aborted: true }
    }
    return { error: true, status: 0, message: '网络异常，请稍后重试' }
  }
}
```
要点：`AbortSignal.timeout` 触发超时时抛 `TimeoutError`，手动 `abort()` 抛 `AbortError`，二者必须分开归一——超时给用户文案，中止返回 `aborted: true` 供调用方静默处理（当前 useApi 调用方虽无手动中止场景，F-11 的 AbortController 也挂在 useAiChat 自己的 fetch 上，但拆分零成本且防误导读）。不归一的话调用方（如 `loadWorks`）拿到的是 DOMException，文案会穿透为「Failed to fetch」类原始信息。`AbortSignal.timeout` 兼容性：Chrome 103+ / Safari 16+ / Firefox 100+，满足现状。

### 3.5 P2：进阶优化

#### F-17 静态路由预渲染（SEO 深层修复，含三项前置改造）

SPA 首屏 HTML 为空壳，搜索引擎对「关于我们/加入我们」等静态内容的收录为零。预渲染是深层修复，但**按现状直接实施必翻车**，以下三项前置改造必须与预渲染绑定进行（v1.1 重写）：

1. **smoke-test 空壳断言失效**：`scripts/smoke-test.js:118` 断言 `/learning` 返回 `/<div id="app"><\/div>/` 空壳——预渲染后 `#app` 内有内容，该断言必挂。需同步改为断言渲染后内容（如匹配页面特征文案）；
2. **Node 服务器不认识预渲染产物**：`server/index.js` 的 `resolveStaticPath`（约 139-164 行）对无扩展名路径永远回退根 `index.html`，`about/index.html` 这类路由目录文件**不会被服务到**。必须增加"路由目录优先"解析：无扩展名路径先试 `<path>/index.html`，不存在再回退根 `index.html`。因此 F-17 不是纯"构建层"任务，`server/index.js` 必须同步改造；
3. **构建顺序冲突**：`npm run build = vite build && node scripts/build-deploy.js`，而 `build-deploy.js:15` 会把根 `index.html` 拷回产物目录，**覆盖预渲染后的首页**。预渲染必须排在 build-deploy 之后，**即把 `package.json` 的 `build` 脚本改为** `vite build && node scripts/build-deploy.js && node scripts/prerender.js`（易漏点：是修改现有 build 脚本，不是另建执行入口）。

**插件选型（v1.1 变更）**：`@prerenderer/rollup-plugin` 多年未维护（Rollup 3 时代），与 Vite 6（Rollup 4）大概率不兼容；`vite-plugin-prerender` 对 Vite 6 的支持需先行验证。鉴于项目已有自定义 Node 服务器，**推荐改用 post-build puppeteer 脚本**：构建完成后起本地服务，依次访问 `/`、`/works`、`/about`、`/learning`、`/join`，将渲染后的 DOM 写为产物目录下的 `<route>/index.html`。不引入 vite 插件依赖，还顺带规避了预渲染插件注入内联状态脚本与 CSP `script-src 'self'` 的冲突。详情页（数据驱动）保持 CSR，后续流量需要时再由后端提供动态 sitemap 或转向 SSR/Nuxt（本站体量不建议）。前置依赖：F-01、F-04、F-09 完成后收益才完整。

**快照时效与渲染环境（v1.2 补充）**：预渲染集合中的 `/`、`/works`、`/learning` 是数据驱动页面（内容来自 API），预渲染产物即**构建期快照**——此后新增作品/学习资料在爬虫端不会反映，直到下次构建。实施时二选一：缩减预渲染集合为纯静态的 `/about`、`/join`（首页保留空壳走 CSR），或明确「预渲染页面为构建期快照，须随内容更新定期重建（挂 CI 定时任务或绑定发布流程）」。另：预渲染执行时 Java 后端必须可达，否则 `/works`、`/learning` 会把错误态/空态 HTML 写进产物——脚本应先探测后端健康（如 `/api/health`）再渲染，失败即中止构建。

## 6. 风险与注意事项

1. **视频重编码**属内容变更，需保留原文件备份并由内容方确认画质（实测 index.mp4 3.95MB / home.mp4 1.23MB，压缩目标合理）；
2. **`no-store` 放开为缓存**时必须只作用于 `/uploads/*`，SSE（`/api/ai/chat`）保持不缓存，否则聊天功能回归；改后用 DevTools Network 逐项核对；
3. **预渲染**（F-17）三项前置改造缺一不可：smoke-test 断言改写、Node 路由目录解析、build-deploy 执行顺序（落实为修改 `package.json` 的 `build` 脚本）；执行时 Java 后端必须可达，否则错误态/空态 HTML 落盘——脚本应先探测健康再渲染、失败即中止；预渲染页面为构建期快照，需随内容更新定期重建；预渲染 HTML 中不得包含登录态相关内容；
4. **`git rm --cached`** 必须覆盖三个目录（`frontend/dist/`、`frontend/frontend/`、`frontend/release/`，共 114 个文件）；执行前先确认部署流程没有"直接从 git 拉产物部署"的路径（`release/` 打包脚本走本地构建，经核实不受影响）；
5. **`envDir: false` 的去留**（F-21）影响 `VITE_API_BASE` 的注入方式，决策前确认无其他位置依赖"前端 .env 不生效"的现状；
6. 所有改动不触碰 Node 层安全响应头与后端消毒链路（§2 已达标项）。
