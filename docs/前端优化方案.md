## 1. 现状总评

两个前端的**代码质量都高于同类项目平均水平**，但问题类型完全不同：

**主站**是「底子好、最后一公里没走完」。2026-09-02 的方案（F 系列）已落地大半——本次复核 **15 项已修复、6 项部分修复、2 项未做**（附录 A）。当前剩余问题集中在三处：发版韧性（chunk 加载失败无兜底）、字节开销（5.43 MB 视频占产物 84.7%）、以及内容安全链（`v-html` 与后端消毒契约脱节）。

**后台**是「工程质量好、规模化后没抽象」。它从未被审查过，本次是首次全面体检，结论分两面：

- **做得好的**：零 `console.log`、零 `TODO`、零 `@ts-ignore`、零 `eval`/`innerHTML`；`request.ts` 的并发 refresh 单飞队列（`refreshPromise ??=`）、`DashboardView.vue:104-115` 的请求序号防竞态、`useChart.ts:82-86` 的 dispose + 监听移除、`AiConfigView` 的密钥脱敏（完整 key 永不回前端）、`socialIcons.ts` 对 `v-html` 的安全约定注释——这些细节体现了明确的工程意识。**内存泄漏专项核查结论：全项目无泄漏**，不需要在这一点上投入预算。
- **真正的短板**：① **首屏体积失控**——Element Plus 全量 + 290 个图标全量注册 + ECharts 全量，首屏 JS+CSS 达 1583.9 KB（gzip 444.9 KB）；② **列表页骨架复制了 12～15 遍后开始各自漂移**，`views/` 下 6003 行中约 2100～2400 行（35%～40%）属可消除的结构性重复，并已漂移出真实 bug（筛选失效、分页边界、表单校验缺失）；③ **当前 `admin/dist/` 是残缺产物**——entry 引用的 70 个 chunk 有 40 个不在磁盘上，含登录页 chunk，直接部署会白屏无法登录。

优先级定义：

- **P0** = 今天就处于错误/缺失状态（功能坏了，或按现状部署会失败）
- **P1** = 高收益或正确性风险（性能大头、错误结果、用户可感强烈）
- **P2** = 体验与可访问性打磨（投入小、专业度提升明显）
- **P3** = 工程化与技术债（防退化，不直接产生用户价值）

### 4.1 P0

#### W-01 懒加载 chunk 失败无兜底（发版韧性）

**现状**：`router/index.js` 无 `onError`；`main.js:8-12` 无 `app.config.errorHandler`；`App.vue:7` 的 `<router-view />` 无 key、无 error 插槽；`App.vue:25` 的 `defineAsyncComponent(() => import('@/components/AiAssistant.vue'))` 未配 `errorComponent`/`loadingComponent`。

**触发路径（真实且高频）**：用户停留在旧版本页面 → 新版本发版（chunk hash 全变）→ 用户点击任意导航 → 浏览器请求已删除的旧 hash chunk → 404 → 动态 import reject → 导航失败。**页面毫无变化、无任何提示**，控制台之外无迹可寻。这是 SPA 最典型的线上事故形态，当前完全无处理，且因为主站做了完整的路由级分割（8 个页面 chunk），触发概率反而更高。

**方案**：

```js
// frontend/src/main.js —— chunk 加载失败时整页重载（最省事且对用户无感的恢复方式）
router.onError((error, to) => {
  const msg = String(error?.message || '')
  if (/Failed to fetch dynamically imported module|Importing a module script failed|error loading dynamically imported module/i.test(msg)) {
    // 防重载风暴：一次会话只自动恢复一次
    if (!sessionStorage.getItem('chunk-reload')) {
      sessionStorage.setItem('chunk-reload', '1')
      location.assign(to.fullPath)
    }
  }
})

app.config.errorHandler = (err, _instance, info) => {
  console.error('[app error]', info, err)
  // 预留上报接入点
}
```

```js
// App.vue:25
const AiAssistant = defineAsyncComponent({
  loader: () => import('@/components/AiAssistant.vue'),
  timeout: 10000,
  errorComponent: () => null,   // 助手不可用不应影响主站
})
```

**验收**：发布新版本后，停留在旧页面的用户点击导航能自动恢复（`location.assign` 重载一次并成功进入目标页）；会话内只重载一次，无重载循环。

#### W-07 AI 流式渲染 O(n²) 与滚动抖动

**现状**：两个问题叠加在同一处。

1. **全量重解析**：`useAiChat.js:57` 每个 SSE 事件都 `appendStreamingText(data)`，而 `AiChatDialog.vue:179` 的 `computed(() => renderMarkdown(store.streamingText))` 每次都对**累积全文**跑 `marked.parse` + `DOMPurify.sanitize`，然后 `v-html` 整块替换 DOM；`:202` 还额外触发一次 `hardenLinks` 全量 DOM 查询。一段 2000 字回答产生几百个分片 = 几百次全量解析 + 消毒 + DOM 重建，**越到后面越卡**；
2. **滚动互相打断**：`AiChatDialog.vue:60` 的消息容器带 `scroll-smooth`（CSS `scroll-behavior: smooth`），而 `:197` 每片都执行 `el.scrollTop = el.scrollHeight` → 每个分片都重新触发一次平滑滚动动画并立即被打断，表现为"追着滚但一卡一卡"。

**方案**：

```js
// 方案 A（推荐，最省 CPU）：流式期间降级为纯文本，收尾时一次性渲染 Markdown
// AiChatDialog.vue —— 流式气泡用 <div class="whitespace-pre-wrap">{{ store.streamingText }}</div>
// finalizeStreaming() 后再切到 renderedHtml 的 markdown 视图

// 方案 B（保留流式 Markdown 观感）：对流式 HTML 做时间片节流
const streamingHtml = ref('')
let rafId = 0, lastRun = 0
watch(() => store.streamingText, () => {
  const now = performance.now()
  if (now - lastRun < 100) {           // 100ms 尾沿节流
    cancelAnimationFrame(rafId)
    rafId = requestAnimationFrame(() => { streamingHtml.value = renderMarkdown(store.streamingText); lastRun = performance.now() })
    return
  }
  lastRun = now
  streamingHtml.value = renderMarkdown(store.streamingText)
})
```

滚动改为 `el.scrollTo({ top: el.scrollHeight, behavior: 'auto' })`，或直接移除 `scroll-smooth`（`:199` 已有 near-bottom 判断，无需平滑）。

**验收**：弱网下 2000 字回答全程输入框不卡顿（Performance 面板长任务 < 50ms）；流式期间滚动跟随连续无抖动。

```js
// composables/useAsyncData.js
export function useAsyncData(loader, { errorMessage = '加载失败，请稍后重试', immediate = true, silent = false } = {}) {
  const data = ref(null)
  const loading = ref(false)
  const error = ref('')
  let seq = 0
  async function load() {
    const cur = ++seq
    loading.value = true
    error.value = ''
    try {
      const result = await loader()
      if (cur !== seq) return                       // 丢弃过期响应（顺带修掉竞态）
      if (result?.error) { error.value = silent ? '' : (result.message || errorMessage); return }
      data.value = result.data ?? result
    } catch (e) {
      if (cur === seq) error.value = silent ? '' : errorMessage
    } finally {
      if (cur === seq) loading.value = false
    }
  }
  if (immediate) load()
  return { data, loading, error, load }
}
```

```vue
<!-- components/StateView.vue —— 三态收敛，含 aria -->
<template>

  <p v-else-if="error" role="alert">
    {{ error }}<button type="button" @click="$emit('retry')">点击重试</button>
  </p>
  <slot v-else-if="!empty" />
  <p v-else>{{ emptyText }}</p>
</template>
```

#### W-14 AI 对话状态与错误处理

**现状**：

1. **职责重叠**：`useAiChat.js:4` 的 `let controller = null` 是**模块级单例**；`:14,15,16,33,72,73` 直接赋值 `store.isLoading`/`avatarState`，与 `stores/aiChat.js:33-53` 已定义的 action 层并存——状态迁移逻辑被切成两半；
2. **英文报错外露**：`useAiChat.js:69` `store.addAssistantMessage(err.message || 'AI 连接失败，请稍后重试')`。fetch 网络失败抛的是 `TypeError: Failed to fetch`，`err.message` 非空 → 用户看到英文技术文案。对照 `useApi.js:37-43` 已把 TimeoutError/AbortError 归一成中文；
3. **无超时**（`useApi.js:16` 有 `AbortSignal.timeout(15000)`，这里没有）；`:28` 非 2xx 时丢弃后端 message 只抛硬编码文案；`:31` 未校验 `response.body` 是否为 null；
4. **清空会话脏写**：`store.clearMessages()`（`aiChat.js:55-58`）不会中断在途流——清空后流式分片仍会 `appendStreamingText`，把已删除会话的内容追加回来。缺"代次（generation）"校验；
5. **无持久化**：对话历史不落任何存储，刷新即丢；`store.messages` 无上限。

**方案**：

```js
// useAiChat.js —— 状态收口到 store action + 代次校验 + 错误归一
let generation = 0

async function streamChat(prompt) {
  const gen = ++generation
  const controller = new AbortController()
  store.setLoading(true)                    // 改用 action，不再直接赋值
  try {
    const res = await fetch(url, {
      signal: AbortSignal.any([controller.signal, AbortSignal.timeout(60000)]),
      // …
    })
    if (!res.ok) throw new Error(await extractMessage(res))   // 保留后端 message
    if (!res.body) throw new Error('AI 服务无响应')
    // …分片循环内：if (gen !== generation) return   // 会话已切换/清空，丢弃
  } catch (e) {
    if (e.name === 'AbortError') { /* 用户主动停止，保留已生成部分 */ }
    else if (e.name === 'TimeoutError') store.addAssistantMessage('AI 响应超时，请稍后重试')
    else store.addAssistantMessage('AI 连接失败，请稍后重试')   // 不再外露 err.message
  } finally {
    if (gen === generation) store.setLoading(false)
  }
}
```
另加：消息数上限（如保留最近 100 条）、`sessionStorage` 持久化、`clearMessages()` 时 `generation++`。

#### A-07 `useTable` 无竞态防护（14 个列表页）

**现状**：全项目防竞态**仅 1 处**——`DashboardView.vue:104-115` 的请求序号。`AbortController`/`CancelToken`/`signal` 在其他位置**零匹配**。而 14 个列表页共用的 `useTable.ts:15-24` 是这样取数的：

```ts
async function load() {
  loading.value = true
  try {
    const result = await fetcher({ ...query })   // ← 无取消、无序号、无去重
    list.value = result.list                     // ← 后到者无条件覆盖
    total.value = result.total
  } finally { loading.value = false }
}
```

**触发路径真实存在**：`WorksListView.vue:13,16` 的分类/状态 `<el-select @change="search">`、`CarouselListView.vue:10` 的 `<el-tabs @tab-change>`、`SqlMonitorView.vue:157-160` 的排序切换。用户快速连点两个筛选值 → 两个请求并发 → **慢的旧请求后返回，把新结果覆盖掉**，表格显示与筛选条件不一致。

**方案**（改一处，修 14 个页面）：

```ts
export function useTable(fetcher) {
  let seq = 0
  let ctrl: AbortController | null = null

  async function load() {
    const cur = ++seq
    ctrl?.abort()
    ctrl = new AbortController()
    loading.value = true
    try {
      const result = await fetcher({ ...query }, { signal: ctrl.signal })
      if (cur !== seq) return                  // 丢弃过期响应
      list.value = result.list
      total.value = result.total
    } catch (e) {
      if (e?.name !== 'CanceledError' && cur === seq) throw e
    } finally {
      if (cur === seq) loading.value = false   // 只有最新请求能关 loading
    }
  }
  onUnmounted(() => ctrl?.abort())
}
```
配套：`request.ts` 的 `http.get(url, params, config)` 已支持第三参透传 `AxiosRequestConfig`（`request.ts:118`），把 `config.signal` 用上即可。同时可在此处一并做 A-14 的分页回退与请求去重。

```ts
}
```

三个问题：① **无 `updated` 钩子**——权限变化后（如 `ProfileView.vue:67` 调 `auth.fetchMe()` 刷新）已移除的按钮不会回来，已授权的也不会消失；② **`removeChild` 绕过 Vue 的 vDOM**——Vue 仍持有该 vnode 引用，后续 patch 同一父节点时可能抛 `insertBefore` 异常（本项目大量 `v-permission` 按钮位于 `#default` 插槽内，如 `FooterView.vue:85`、`ServicesView.vue:36`，每次 `load()` 重渲染都会 patch 这些插槽；**实际是否复现未确认**，但这是已知反模式）；③ 若元素尚未插入 DOM，`el.parentNode?.` 静默失败，权限判断被完全跳过。

**当前不产生可见错误**，因为 `router/index.ts:214-221` 的守卫在进入路由前 `await auth.fetchMe()`，权限在组件 mount 前已就绪——但这是**隐性契约**，一旦有人把 `fetchMe` 改成非阻塞预热，所有 `v-permission` 元素会集体消失。

**方案**：改 `el.style.display = 'none'`（配合 `updated` 钩子），或提供 `<PermissionWrapper>` 组件用 `v-if` 实现。

#### A-23 编辑页无"未保存离开"提示

全项目 `beforeRouteLeave`/`onBeforeRouteLeave`/`beforeunload` **零匹配**。`WorkEditView.vue`（187 行，含富文本编辑器）与 `NewsEditView.vue`（152 行）的"返回"按钮是裸跳转：

```vue
<el-button @click="$router.back()">返回</el-button>
```

**影响**：在富文本编辑器里写了半篇文章，误点返回 → 全部丢失，无任何拦截。这是内容管理后台里代价最高的误操作之一。

#### A-24 ECharts resize 无防抖、无 ResizeObserver、deep watch

先明确纠正一个常见误判：**这一块没有内存泄漏**。`useChart.ts:82-86` 的清理是正确的：

```ts
onUnmounted(() => {
  window.removeEventListener('resize', onResize)   // ✅
  chart?.dispose()                                 // ✅
  chart = null                                     // ✅
})
```

但有三个真实问题：

1. **`resize` 无防抖**（`:73-75`）：拖拽窗口时浏览器每秒触发数十次 resize，每个图表实例都做一次完整重排；
2. **无 `ResizeObserver` → 侧边栏折叠后图表尺寸错乱**（功能缺陷）：`AdminLayout.vue:37` 点击折叠只改 `collapsed`，`:120` 的 `transition: width 0.25s` 把侧栏从 220px 收到 64px——**这不触发 `window.resize`**，所以图表容器宽度变了但 `chart.resize()` 永不调用 → 图表按旧宽度渲染，右侧被裁切或留白。全项目 `ResizeObserver` 零匹配；
3. **`deep: true` 深度监听整个 option**（`:88-90`）：`DashboardView.vue:119-147` 的 `trendOption` 在 `summary` 变化时**整体重建对象**，deep 会遍历 90 天双序列（180 个数据点）+ 完整 option 树。因为 computed 返回新引用，**浅监听即可捕获**。

```ts
function onResize() {
  clearTimeout(resizeTimer)
  resizeTimer = window.setTimeout(() => chart?.resize(), 150)
}
onMounted(() => {
  render()
  window.addEventListener('resize', onResize)
  ro = new ResizeObserver(onResize)
  if (elRef.value) ro.observe(elRef.value)     // 覆盖侧栏折叠等容器变化
})
onUnmounted(() => {
  window.removeEventListener('resize', onResize)
  clearTimeout(resizeTimer)
  ro?.disconnect()
  chart?.dispose(); chart = null
})
if (typeof option !== 'function') watch(option, render)   // 去掉 deep
```
